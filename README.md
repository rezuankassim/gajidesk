# GajiDesk

A local Malaysian monthly payroll demo for one employer and salaried staff. The seeded company, employees, statutory entries, and payment details are fictional.

## Run the demo

Use PHP 8.5 with SQLite, Composer, and Node.js 22 or later.

```sh
composer install
npm ci

# On a fresh checkout. Keep an existing .env and APP_KEY.
test -f .env || cp .env.example .env
touch database/database.sqlite
if ! grep -q '^APP_KEY=.' .env; then
    php artisan key:generate
fi

php artisan migrate
php artisan db:seed --class=PayrollDemoSeeder
npm run build
php artisan serve --host=localhost --port=8000
```

Open the app’s **Log in** page. Sign in with `admin@pandan.example` and `demo-payroll-2026`. The seeder is limited to local and testing environments and skips an existing payroll workspace. To repeat the walkthrough from scratch, point `DB_DATABASE` at a new SQLite file, migrate and seed it, and start the server with `--no-reload` when supplying that variable in the shell. Keep the existing key for any database you want to keep reading.

## Five-minute walkthrough

1. Open the current worksheet. Nur Aina Salleh is unchanged, Daniel Wong has an RM200 bonus, and Ethan anak Jali needs a partial-month review. Use **Choose month** to see the prior finalised run.
2. Open Nur Aina’s row, select **Add adjustment**, enter a bonus of `125.00`, and save. Her provisional net moves from RM3,577.95 to RM3,702.95 and the worksheet subtotal increases by RM125. For the fictional demo, keep the prefilled statutory figures and confirm the review.
3. Open Ethan’s flagged row. Enter `1800.00` as his verified prorated basic and use “Fictional Sarawak proration for demo” as the explanation. Save, then enter the fictional review figures below. Select **Manually verified** for each entry and use “Fictional demo verification” as the reason.

    | Component | Employee (RM) | Employer (RM) |
    | --------- | ------------: | ------------: |
    | EPF       |        350.00 |        410.00 |
    | SOCSO     |         15.75 |         55.15 |
    | EIS       |          6.30 |          6.30 |
    | PCB / MTD |          0.00 |               |

4. Choose **Review & finalise**. Check the four employees and RM12,136.80 net payable. Finalise, open Nur Aina’s payslip, and select **Print payslip**.
5. Choose **Review payment**. Confirm the date, four recipients, and RM12,136.80 in transfers, then select **Download Payment preview CSV**. Nur Aina’s account starts with zero in the raw file. To inspect it in a spreadsheet, import the account column as text. **Maybank upload file** stays disabled. The download records an export event and leaves payment approval in the bank portal.

Employee and salary changes apply when creating a new worksheet. Finalised amounts and payslips use their stored snapshots. Use **Correct beneficiary** on a finalised payment review to record a reason and replace payment details for that run. Earlier downloads retain their original contents.

## What the client and bank still need to verify

- Confirm the employer’s work jurisdiction, employee eligibility, verified partial-month pay and adjustments, and the applicable statutory amounts for each employee and month. The POC records explicit verified amounts or reasons for inapplicability. It adds and subtracts in integer sen and accepts up to two decimal places. It performs no statutory or proration calculation. Use the official sources for verification. [KWSP Third Schedule](https://www.kwsp.gov.my/en/epf-act-1991-third-schedule) · [PERKESO rates and schedules](https://www.perkeso.gov.my/en/rate-of-contribution) · [HASiL PCB/MTD specifications](https://www.hasil.gov.my/en/majikan/jadual-pcb-dan-spesifikasi-data/)
- With Maker access, download the original blank workbook from **Maybank2u Biz → Bulk Payment → Bulk Payment by Entries & File Upload → File Upload/Download**. Provide that workbook and a matching sanitised CSV saved from it with fictional details. The Maybank step-by-step guide and 3 August 2021 Maker walkthrough show the download location and a sample layout. The portal’s exact workbook version and allowed bank and ID values remain pending. The public limits are 100 records and RM250,000 per file. [Maybank guide](https://www.maybank2u.com.my/iwov-resources/pdf/business/M2Ubiz_BulkPayGuide.pdf) · [Maker walkthrough](https://www.maybank2u.com.my/iwov-resources/pdf/business/Maybank2uBiz/how-to-perform-bulk-payment.pdf) · [Published limits](https://www.maybank2u.com.my/maybank2u/malaysia/en/business/payment_solutions/maybank2u_biz/maybank2u_biz.page)
- Confirm supported recipient banks, identifiers, employer rows, field lengths, references, crediting dates, and CSV serialization against that workbook. Validate generated bytes against a sanitised fixture first, then have the client confirm that their portal accepts the file. The current CSV is an internal preview and has no Maybank template match or portal acceptance.
- Use a separately provisioned verified payroll administrator before loading real records. Keep `APP_KEY` private, set `APP_DEBUG=false`, and serve over HTTPS outside local development.
